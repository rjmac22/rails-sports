# Project principles

Inside Rails starts with sporting questions, not statistical techniques.

Every article should follow this sequence:

1. **Start with a genuine sporting debate.**
2. **Build a rigorous model.**
3. **Test competing ideas.**
4. **Show the evidence.**
5. **Explain what it means in plain English.**

## Working philosophy

We model real sporting decisions.

Every project should begin with a decision that someone in sport genuinely has to make: a manager, coach, captain, referee, sporting director or informed supporter.

The aim is not to demonstrate mathematics for its own sake. The aim is to discover whether evidence can improve that decision.

Before beginning a project, ask:

- Is this a real sporting decision?
- Would knowledgeable people reasonably disagree?
- Can we model it credibly?
- Will the answer change how someone thinks?
- Is the result interesting even if the effect is small or nonexistent?

If the answer to several of these questions is 'no', the project should probably not proceed.

**The simulation is the engine. The sporting question is the product.**

A technically impressive model is not sufficient by itself. The work should answer a question that matters outside the notebook and should not require the reader to care about the mathematical machinery before they care about the result.
